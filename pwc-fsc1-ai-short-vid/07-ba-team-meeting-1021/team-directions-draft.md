# BA 團隊發展方向：選項草稿（11/6 組會用）

Luke 要每個人提出 2–3 項 BA 團隊發展方向，下次組會一起審視並定案。
下面 5 個選項都對應到 Luke 10/21 簡報的一年目標（第 6 頁：品質、效率、價值、成長）或三年目標（第 7 頁），並結合會議中大家實際提到的做法。請挑 2–3 個，用自己的話改寫。

---

## 選項 A：建立團隊共用的「AI 協作需求範本＋審查清單」⭐ 推薦

| | |
|---|---|
| 要做什麼 | 把「訪談 → AI 整理 → 人工審查 → 需求確認」做成團隊共用的範本：會議紀錄整理提示詞、需求文件格式、AI 產出的人工審查清單（有沒有符合原始目的、有沒有 AI 語氣、依據可不可以追溯） |
| 為什麼 | 對應一年目標 02「AI 協作成為標準做法」，並設審查與回顧機制。會議中 Luke 多次要求 AI 產出要人工 review，Kevin 也提到 AI 看不到公司內部規格，有共用範本就能補這個缺口 |
| 一年後怎麼衡量 | 範本在至少 2 個專案實際使用；每案記錄 AI 用在哪些步驟、省下多少時間、退件或返工次數 |
| 我能貢獻什麼 | AI 開發框架簡報裡已經整理過「人在哪一步把關、通過標準怎麼定」，可以轉成 BA 版的審查清單 |

## 選項 B：用 AI 快速做互動原型，讓客戶提早驗證需求 ⭐ 推薦

| | |
|---|---|
| 要做什麼 | 把 Mia 在國發專案用 AI 做互動式 HTML 原型的做法，整理成團隊都能用的標準流程：什麼情況適合做、提示詞怎麼下、原型怎麼交給開發與測試 |
| 為什麼 | 對應簡報第 5 頁「AI 把需求從對話轉為可驗證、可落地的成果」和一年目標 03「高價值顧問模組可見」。這也是外部 BA 和客戶自建團隊最大的差別：不只寫需求，還能馬上做出東西給客戶驗證 |
| 一年後怎麼衡量 | 至少 2 個專案用原型確認需求；記錄原型階段就發現的需求落差數量 |
| 我能貢獻什麼 | 這正是我的發展方向「AI builder＋BA」：分析需求，也能用 AI 快速做出成果 |

## 選項 C：每月分享沉澱成「團隊知識庫」⭐ 推薦

| | |
|---|---|
| 要做什麼 | 每月 10–15 分鐘的組內分享、外訓心得、證照經驗，統一整理成一頁格式（一個重點、一個啟發、一個可應用做法），放進共用資料夾 |
| 為什麼 | 對應簡報第 12 頁「把學到的變成團隊共同資產」和一年目標 04「能力地圖與培訓啟動」。新進成員也可以用這個知識庫快速進入狀況 |
| 一年後怎麼衡量 | 累積至少 10 份分享紀錄；每人至少貢獻 2 份（剛好對應個人目標「內訓分享 ×2」） |
| 我能貢獻什麼 | UWOS 文章分享已經是第一份，可以當格式範例 |

## 選項 D：每個案子建立「需求 → 驗證」對照

| | |
|---|---|
| 要做什麼 | 每個需求都對應到驗證方式（測試案例、原型確認或客戶簽核），需求變更時同步更新 |
| 為什麼 | 對應一年目標 01「端到端交付檢核」。和泰專案的經驗是範疇一直擴大、無法收斂，有對照表才看得出哪些需求已經驗證、哪些是新增的 |
| 一年後怎麼衡量 | 每案都有對照表；上線前沒有驗證到的需求數量 |
| 備註 | 和測試、專案管理比較相關，Kevin、Mia 可能比較適合主導 |

## 選項 E：用 AI 短影片或簡報對外說明 BA 能做什麼

| | |
|---|---|
| 要做什麼 | 把團隊的方法（例如 AI 協作需求流程、人機分工的關卡）做成短影片或一頁說明，用在提案和研討會 |
| 為什麼 | 對應一年目標 03「高價值顧問模組可見」，讓客戶和其他團隊知道 BA 能提供什麼 |
| 一年後怎麼衡量 | 至少 1 支影片或 1 份說明實際用在提案或研討會 |
| 備註 | 和我目前的 AI 短影片工作重疊，可以當作我的個人貢獻，不一定要列成團隊方向 |

## 建議組合

**A＋B＋C**：
- A 是「怎麼用 AI 用得安全」，B 是「用 AI 做出客戶看得到的成果」，C 是「讓經驗留在團隊」。
- 三項剛好對應一年目標的效率、價值、成長，而且每項都有可以衡量的成果。
- 三項都能連到我自己的發展方向和個人目標，講的時候比較有說服力。
